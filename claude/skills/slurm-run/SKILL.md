# Slurm に流す

r995 の Slurm の待ち行列に重い計算を流す。排他のジョブは待ち行列が 1 本ずつ実行するので、依存の無いジョブは一度に投げる
（下の「複数のジョブを待つ」）。投げるのは `~/.claude/scripts/slurm-run.sh` だけで、`sbatch` は直接使わない。

## 現在の待ち行列

!`~/.claude/scripts/slurm-queue.sh`

ジョブは走る順（パーティション `timed`、`main` の順。その中は走っているもの、止められたもの、待っているものの優先度の順）に並ぶ。

- 1 行目: ジョブ番号、状態、パーティション（既定の `main` か、時間を記録する `timed`）、優先度、区分、見積もり、開始の見込み、名前、参照
- 2 行目: 目的（結果が何を決めるか）
- 3 行目: 連絡先（git のブランチ、投げた場所、`commit=` 投げた時点の HEAD の短い hash、`claude=` セッション、排他でなければ `shared-cpus=`）
- 一覧の印の意味は `NOTE:` の行に、`ORDER:` の行の扱いは `NEXT:` の行に出る
- 経過と CPU 数は `squeue` で読む

連絡先が自分のブランチでないジョブは、ほかのエージェントのもので、取り消さない。順番を変える手段と自分のジョブの取り消しは下の「順番」。

## 流すかどうか

資源で決める。時間の長さだけでは決めない。次のどれかに当たれば流す。迷ったら流す。

- 多くのコア（目安で半分以上）を 5 分以上使い続ける
- メモリを大きく使う（目安で搭載量の半分以上）
- 時間を記録する測定（短くても。区分 `timed` で投げる）

1 コアの処理（テスト、lint、比べるツール）と数分のビルドは、時間がかかっても手元で実行する（待ち行列では、ほかのセッションの
長い計算の後ろで待つ）。時間を記録する排他のジョブが走っている間の手元の計算は、下の「排他のジョブが走っている間」。

## 投げ方

```bash
cd <作業ディレクトリ> && ~/.claude/scripts/slurm-run.sh --class <区分> --ref '<参照>' --purpose '<目的>' -t <見積もり> <名前> '<コマンド>'
```

例:

```bash
cd ~/github/solver && ~/.claude/scripts/slurm-run.sh --class decision --ref '#0200' --purpose '大きい入力で反復が収束するかで、#0200 の修正方法を決める' \
  -t 150 solver-large-grid 'target/release/solver cases/large-grid.toml'
```

出力の `ERROR:`、`WARN:`、`NEXT:` の行に従う。
下の例の `<区分と目的>` は `--class <区分> --ref '<参照>' --purpose '<目的>'` を表す。

区分が `timed` でないジョブは、パーティション `main` に入り、`timed` のジョブに止められうる（続きから再開し、結果は変わらず、
終わりが遅れるだけ）。時間を記録するジョブは、下の「時間を記録するジョブ（--timed）」のとおり区分 `timed` で投げる。

### 区分と目的

- `--class` は次の 4 つで、上ほど先に流す。結果の使い道で選び、迷ったら下の区分にする
  - `timed`: 時間を記録する測定（記録に書く時間、高速化の測定）。`--timed` を付けなくてもパーティション `timed` に投げる
  - `record`: 記録に載せる本番（記録に書く数値を出す計算と、その入力になる成果物の作り直し）
  - `decision`: 決定に要る確認（方式を選ぶ、原因を確かめる、issue を閉じるかを決める計算）
  - `trial`: 検討（結論を変えない試行、開発中の確認）
- `--ref` は、きっかけの issue か ADR の番号（`'#0200'`、`ADR-NNNN`、複数は `'#0200,ADR-NNNN'`）。無いときは `'- <理由>'`（`'- nixfiles の実機の確認で、記録の番号が無い'`）
- `--purpose` は、結果が何を決めるかの 1 文（「〜かで、〜を決める」）。何を計算するかでなく、結果を見て何を選ぶかを書く。

### 見積もり、名前、作業ディレクトリ

- `-t` は、上限ではなく、待ち行列の開始の見込みに使う見積もりで、超えても止まらない
- 見積もりは過去の実績の 1.3 倍ほどを書く。`~/.claude/scripts/slurm-history.sh --by-name` が、ジョブ名ごとの見積もり、実績、比
  （`RATIO`、`MAX_RATIO`）、`MAX_RSS` を出す。
- 実績のない計算は、小さい入力で測って見積もる。種類ごとに 1 段階（1 状態）を測ってから本数を掛ける
- 過去のジョブの測定（時間、`MaxRSS` などのメモリ）を、見積もりに使う、「前は同じ入力で X だった」と比べる、依頼の前提に書くときは、
  先に `~/.claude/skills/slurm-run/references/past-jobs.md` を読み、取るジョブがコマンドと中身の同じ排他のジョブかを確かめる
  （`--by-name` の表は名前でしか結ばず、名前の似たジョブが同じ仕事をしたとは限らない）
- 名前は `<ツール>-<題材>`（`solver-large-grid`、`bench-sort-radix`）。
- ジョブは `slurm-run.sh` を呼んだときの `$PWD` で、`--export=ALL`（今の環境変数、nix の開発シェルの PATH を含む）で走り、
  連絡先にもその `$PWD` が入る。必ず `cd <作業ディレクトリ> && ~/.claude/scripts/slurm-run.sh ...` の形で呼ぶ
  （`cd ... &` と `&` で切ると、ジョブは cd の前の場所で走る。クォートしたコマンドの中の `cd` は連絡先に反映されない）。
- ジョブの中のプログラムの時間とメモリは、`TIME:` 行と `sacct -j <番号>.batch -o Elapsed,MaxRSS`（MaxRSS は `.batch` の行に
  だけ入る）で取る。

## 順番

パーティション `main` の待っているジョブは、区分の順（`timed` > `record` > `decision` > `trial`。同じ区分は今の順。投げたジョブは自分の区分の末尾、
`--top` なら先頭）に流す。
`slurm-run.sh` が `main` に投げるたびに並べ直すので、投げる側は何もしなくてよい。パーティション `timed` は区分で並べず、
投げた順に走る。`timed` の待っているジョブは、`main` の待っているジョブより先に走る。

- 急ぐ短いジョブは `--top` で投げる。`main` では自分の区分の先頭に出て、上の区分のジョブは追い越さない。`timed` では待っている
  ジョブすべての前に出る。区分の順を越えて 1 本を先に出す仕組みは無い
- `--top` は、どちらのパーティションでも、待っているほかのセッションのジョブを後ろに回すので、見積もりが数分のジョブに限る
- 走っているジョブの終わりを待てない数分の計算は、区分を変えずに `--timed` で投げる（下の「時間を記録するジョブ（--timed）」）
- 順番を変えるのは、`slurm-run.sh` の並べ直しと `--top`、`ORDER:` の行の `scontrol top`、`--timed` だけ。
- ほかのエージェントの走っているジョブは、下の区分でも止めない（区分は待っているジョブの順だけを決める）。
- 自分が投げたジョブ（連絡先が自分のブランチで、番号を `JOB:` の行で控えたもの）で目的が無くなったもの（見込みが外れた、
  入力の誤りに気づいた、など）は、理由と番号を報告に書いて `scancel <番号>` で取り消す。同じ `&` と `wait` で待っているジョブや後ろの `&&` のジョブが残るときは、その扱いも報告に書く。
  auto mode の分類器に `scancel` を拒まれたら、番号と理由を親（委任した側。親がいなければユーザー）に送り、親が取り消す
- 依頼に本数の上限を置くのは、待ち行列が混む（ほかのセッションのジョブが待っている）ときだけにする

## 時間を記録するジョブ（--timed）

```bash
cd <作業ディレクトリ> && ~/.claude/scripts/slurm-run.sh --class timed --ref '<参照>' --purpose '<目的>' -t <見積もり> <名前> '<コマンド>'   # 時間を記録する
cd <作業ディレクトリ> && ~/.claude/scripts/slurm-run.sh --class decision --ref '<参照>' --purpose '<目的>' --timed -t <見積もり> <名前> '<コマンド>'   # 数分の急ぐ計算
```

時間を記録するジョブ（記録に書く時間、高速化の測定）は区分 `timed` で投げる。
数分の急ぐ計算は、区分をそのままにして `--timed` を付ける。どちらもパーティション `timed` に排他で入り、待っている `main` の
ジョブより先に走り、走っている `main` のジョブをすべて止めて（`SUSPENDED`）実行し、自分は止められない。止められたジョブは、
`timed` のジョブが終わると続きから再開する。

- 時間を記録せず、数分で終わらないジョブ（成果物の作り直し、精度の記録、確認の計算）は、区分 `timed` も `--timed` も付けずに
  `main` へ投げる（付けると、追い越された `main` のジョブが待ち続ける）
- `timed` のジョブどうしは止め合わず、投げた順に走る。長い `timed` のジョブが走っている間は、測定も
  急ぐ計算も待つ。待っている `timed` のジョブの中で先に出すのは `--timed --top`
- 止められたジョブはメモリに残る。投げる前に、走っているジョブのメモリ（`sstat -j <番号>.batch -o MaxRSS`。`.batch` が要る）と
  投げる計算のメモリの合計が、搭載量（RealMemory 86000 MB）に収まることを確かめる（超えると OOM killer がどちらかを殺す）
- 止められたジョブは、持っているロック（cargo のビルドディレクトリ、DVC の `.dvc/tmp/lock`、flock）を持ったまま止まり、同じ
  ロックを取る `timed` のジョブとは、どちらも進まない（DVC はすぐ失敗する）。走っている `main` のジョブと同じ target ディレクトリ、DVC のリポジトリでは投げない（同じ worktree は `slurm-run.sh` が止める）。worktree によらないロック（cargo の `$CARGO_HOME` の
  パッケージのキャッシュ、nix の評価のキャッシュ）でも起きうる。`timed` のジョブがロックを待って進まなければ（ログに
  `Blocking waiting for file lock` など）、自分の `timed` のジョブを取り消し、止められたジョブが終わってから投げ直す
- 止まるのはジョブのプロセスだけで、ジョブが頼んだ外のデーモンの仕事（nix-daemon のビルドなど）と、親から外れたプロセス
  （デーモン化、二重 fork）は走り続け、測定の時間を乱しうる

## 複数のジョブを待つ

/delegate の担当と、55 分を超える計算を投げる親は、この節の `a & b & wait` の形を使わず、依存の無いジョブを 1 本ずつ別の
background で投げ、依存のあるジョブだけ `a && b` の 1 行で投げる（/delegate の「作業中の規則」の待ちの項）。担当が投げて待つか
報告して終えるかは、hook（guard-delegate-wait）と `wait-step.sh` が 55 分の線で決める（同項）。
それ以外の呼び出し手は、関係するジョブをまとめて 1 つの background のコマンドで投げ、すべて終わってから報告する:

```bash
cd <作業ディレクトリ> && { ~/.claude/scripts/slurm-run.sh <区分と目的> -t 30 a '…' & ~/.claude/scripts/slurm-run.sh <区分と目的> -t 30 b '…' & wait; }   # 依存が無いとき。同時に投げ、待ち行列に任せる
cd <作業ディレクトリ> && ~/.claude/scripts/slurm-run.sh <区分と目的> -t 30 a '…' && ~/.claude/scripts/slurm-run.sh <区分と目的> -t 30 b '…'   # b が a の出力を使うときだけ。a が失敗したら b は投げない
```

- `&&` は、後ろのジョブが前のジョブの出力を使うときだけ。独立なら `&` と `wait`（`&&` の後ろのジョブは、前が終わるまで squeue に
  出ず、親が取り消せない）
- `cd` は `{ }` の前に置く（`cd d && a & b` は a だけが d で走る）
- 成否は、1 本なら `slurm-run.sh` の終了コードと `EXIT:` で、`wait` で待った複数なら `RESULT:` の行で見る
- 終わると通知が届くので、通知を待つ（Monitor や until のループを重ねない）
- ジョブが書いた出力のファイルは通知の後に読む。

区分 `timed` と `--timed` のジョブにも同じ規則が当たる（`&` で同時に投げたジョブどうしの順は決まらない）。`timed` のジョブを `&&` で
つなぐときは、`~/.claude/skills/slurm-run/references/timed-chain.md` を読む。

## 排他のジョブが走っている間

時間を記録する排他のジョブ（パーティション `timed`）が走っている間、そのジョブの計算ノードの上の全コアの計算と、nix のビルド
（`nix build`、`nix flake check`、rebuild。ほかのホストからも計算ノードに投げられる）は hook が止め、修正方法を示す（`taskset` で
1 コアに限る、待つ、手元でビルドするなど）。`run-checks.sh` は自分で 1 コアに限って遅く実行する。`main` の排他のジョブは時間を
記録に使わないので、その間の手元の計算は限らない。

- 排他のジョブ中の手元の試行の時間は、測定から外す
- 手元のビルドや 1 コアの計算、Slurm 外のプロセス（nix-daemon のビルドなど）との重なりは、数 % のブレとして受け入れ、追加の隔離の
  仕組み（測定から物理コアを外す、手元の計算を止める hook）は作らない（`--timed` の一時停止は、経過時間を壊すので残す）
- 測定の時間を比べるときは、同じ時間帯の手元の計算と Slurm 外のプロセスを、差の原因の候補に先に挙げる。高速化の判断は、同じ
  ジョブの中の A/B、プログラムが出す時間の内訳、反復の回数で比べる

## ログと時間

全ジョブの履歴は `sacct` で、名前や期間で絞り、メモリの最大値も読める:

```bash
sacct -S <日付> --name=<名前> -o JobID,JobName,Partition,Elapsed,TimeLimit,State,MaxRSS,Suspended
```

- 記録に書く時間は、パーティション `timed` のジョブ（区分 `timed` か `--timed`）の、TIME 行に印の無い `elapsed` だけを使う
- 番号の分かったジョブの時間（見積もりや依頼の前提に使う値）は、番号と時間が同じ行にある形で読む:
  `sacct -j <番号>[,<番号>…] -X -o JobID,JobName,Partition,Elapsed,Suspended,State` か、`TIME:` 行の `job=`。何本かのログを
  1 回の `grep` で読むときは、`-H` でファイル名を行に残す（出力の順は引数の順と限らない）
- ジョブが止まった理由（メモリの疑いを含む）を調べる、報告や依頼に書くときは、`~/.claude/skills/slurm-run/references/stop-reason.md`
  を読む。`MaxRSS` と `ReqMem` を比べて推さない（r995 の Slurm はジョブのメモリを制限せず、メモリで止めるのはカーネルの OOM killer）

## 排他でない投げ方（-c）

```bash
cd <作業ディレクトリ> && ~/.claude/scripts/slurm-run.sh <区分と目的> -c <コア数> -t <見積もり> <名前>-shared '<コマンド>'
```

`--exclusive` を付けず、`<コア数>` の CPU だけを取る。時間を記録しない長い計算（何時間もかかる計算、開発中の試行）向け。

- コア数は Slurm の CPU（ハードウェアスレッド）で数える。プログラムを 16 スレッドで実行するなら `-c 16`（物理コア 8）
- r995 は 16 物理コア × SMT で論理 32。Slurm はスレッドを CPU に束縛しないので、共有ジョブは物理コアを SMT で共有する。
  長い共有ジョブと開発の共有ジョブを重ねるときは `-c 16` + `-c 16` を基本にする（`-c 24` + `-c 8` のように偏ると、少ない側が
  極端に遅くなる）
- 排他でないジョブどうしは重なる。排他でないジョブが走っている間、あとから投げた `main` の排他のジョブは、短くても待つ。
  `--timed` のジョブは待たず、走っている排他でないジョブも止めて始まり、止めたジョブとメモリを分け合う
- メモリは Slurm が数えず、ジョブごとにも制限しない。排他でないジョブを複数流すときは、メモリの合計が搭載量
  （RealMemory 86000 MB）を超えないよう自分で数える（超えるとカーネルの OOM killer が長い計算を殺す）
