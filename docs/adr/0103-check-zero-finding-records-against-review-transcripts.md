# ADR-0103: 0 件のローカルレビューの記録は、その周の /code-review の記録に PR の差分が入っているときだけ付ける

## 背景

`record-local-review.sh` は、その head で /code-review を呼んだことを count-review-rounds の行で確かめる（#281）が、
呼んだ周が差分を読んだかは確かめない。/code-review の 0 件の返答（low は `(none)`）は、読んだ上での 0 件か、何も読まずに
返した未実施かを、返答からは見分けられない。

- 2026-11-19、low が読まずに `(none)` を返した周が 5 回あった（#340 の本文。テストだけ、文書だけ、大きな差分の周）
- 2026-11-20、low の返答が `(none)` だけの周が少なくとも 6 回あり、扱いが人ごとに分かれた。親は transcript を手で grep して
  確かめ（3 回）、担当 2 人は同じレベルでもう 1 周回し、担当 1 人は transcript で確かめた（#340 の 2026-11-20 のコメント）

/code-review は、Skill の呼び出しごとにサブエージェントを起動し、その記録を
`<設定の場所>/projects/<プロジェクト>/<セッション>/subagents/agent-<id>.jsonl` に、隣の `agent-<id>.forked-skill.json`
（`skillName` が `code-review`、`effort` がレベル）とともに置く。担当（サブエージェント）が回した周も、同じセッションの
`subagents/` に置かれる（2026-11-20 のセッションの `.meta.json` の `spawnDepth` が 2 の記録）。記録の最初の行は
`` Review target: `<対象> <焦点>` `` で始まる依頼文で、tool の結果（`git diff` の出力、Read の本文）は `type` が `user` の行の
`tool_result` に入る。大きな出力はファイルに置かれ、tool の結果は先頭の約 2KB と置き場のパスだけになる。この形は
Claude Code の公開の仕様ではない。

## 決定の要因

- 誤って「読んだ」と判定する（未実施を通す）より、誤って「読んでいない」と判定する（回し直しになる）方がよい
- ただし、読んだ周を常に「読んでいない」とするなら入れる意味が無い。実物の記録で両方の場合を確かめる
- 記録の 1 件ごとに手で grep する作業と、要らない回し直しの両方を無くす

## 検討した案

- 案 A: /git-merge の「終わり」の項に「修正がテスト、`tests/` の下、文書だけのときは medium」と足す（#340 の候補 1）。
  文の規則で、読まれない経路が残る。low が大きな出力のファイルを開かない周（補足の a037d03）は、テストや文書と関わらない
- 案 B: `review-level.sh` が、前の周の HEAD からの差分のうち low の範囲に残る行数で `LEVEL` を決める（#340 の候補 2）。
  回す前のレベルは決まるが、回した周が読んだかは確かめない
- 案 C: `record-local-review.sh` が 0 件の記録のときに「読んだファイル」を引数で受けて差分と照らす（#340 の候補 3）。
  読んだファイルは自己申告のままで、返答と同じく確かめられない
- 案 D（採用）: `record-local-review.sh` が、その周の /code-review の記録の tool の結果に、差分の追加行が入っているかを確かめる

案 D の中で比べた基準（2026-11-20 に、/code-review の記録 97 件で測った。測り方は補足）:

- D1: PR の差分（base...head）の追加行の全部を、1 件の記録に求める。直した後の周は直した差分を焦点に読むので、焦点の周が
  外れる。D4 で「読んだ」とした 0 件の周 18 件のうち 10 件は、追加行の 0〜86% しか入らない（どれも焦点の差分は読んでいた）
- D2: 割合のしきい値（例えば 80%）。ファイルを 1 つ読まなかった周が 93%、96% になり（補足の a016e8f、a02a67d）、しきい値は
  読まなかったファイルを通す
- D3: ファイルごとに 1 行でも入っていれば読んだとする。テストだけの差分で、10 行のうち 2 行だけが入った周（#336 の
  abe31f1。low がテストを外した）を通す
- D4（採用）: 前の周の head から変わった追加行の全部を、その head の周の記録を合わせたものに求める

記録の引き方で比べた案:

- 周の行の時刻に近い（90 秒以内に始まった）記録を取る: 試作で使ったが、同じ head を続けて回した周と、別のブランチで同じ頃に
  回した周を分けられない
- 記録する側の `CLAUDE_CODE_SESSION_ID` のセッションを探す: 回したセッションと記録するセッションが違う（/clear の後、
  引き継いだ後）と引けない
- count-review-rounds の行に、回したセッションの ID を書く（採用）: hook は Skill の呼び出しの入力の `session_id` を持っている

## 決定と理由

案 D と基準 D4 にする。

- **行**: count-review-rounds は、周の行に回したセッションの ID を足す（`<HEAD> <UNIX 秒> <セッション>`）。前の版の行
  （2 つの欄）も読む
- **記録を探す**: 0 件の記録のとき、その head の行のセッションの `subagents/` から、`.forked-skill.json` の `skillName` が
  `code-review` で、その head の最初の行より後に始まった記録を取る（設定の場所は `CLAUDE_CONFIG_DIR`、無ければ `~/.claude`）。
  前の周の記録と、差分を書いた担当などほかのサブエージェントの記録は、この周に読んだことを示さないので数えない
- **求める行**: PR の差分（`gh pr diff`）の追加行のうち、前の周の head（同じブランチの行で、この head の最初の行の前にある
  別の head）から変わった行（`git diff <前の head> <head>` の追加行と重なるもの）。前の周が無いか、変わった行が無い（rebase
  だけ、消すだけの修正）なら、PR の差分の追加行の全部。lock のファイル（`*.lock`、`*-lock.json`、`*-lock.yaml`）は外す。
  テストのファイル（パスに `test` か `fixture` を含む、`spec` のディレクトリの下）は、ほかのファイルの行があれば外す。行は
  前後の空白を除き、先頭の 200 文字で比べる（Read は 2000 文字を超える行を切る）
- **判定**: その head の周の記録の tool の結果を合わせたものに、求める行が全部あれば記録する。1 行でも欠ければ記録せず、
  欠けたファイルと行の数を出し、レベルを 1 段上げて（low は medium、medium と high は high）欠けたファイルを焦点にした
  /code-review を `NEXT:` で示す。焦点の周はそのファイルだけを読むので、前の周と合わせて数える
- **引けないとき**: 行にセッションが無い、記録が無い（別の機械で回した、記録が消えた）、PR の差分を取れない、比べる追加行が
  無いときは、`--unlogged <理由>` を求め、理由を記録のコメントに残して付ける（行の無い head の `--unlogged` と同じ考え方）。
  読んでいないと分かった周は、`--unlogged` を付けても付けない
- **変えないもの**: 指摘が 1 件以上の記録と、行の無い head の `--unlogged` の記録は、今までどおり付ける。指摘のある周は、
  指摘が読んだことを示す

テストの名前の範囲を広く取るのは、low が外すファイルを自分で選ぶため（`':!*test*' ':!*fixtures*'` を渡した周があった）。
狭い範囲では、外して読まなかったテストの行を欠けと数え、読んだ周を「読んでいない」とする。テストだけの差分では、テストを
読まない周を「読んでいない」とする（#340 の本文の #336 の例）。

### 帰結

- 2026-11-20 に実物の記録で確かめた結果（補足）では、返答が `(none)` の low の周 25 件のうち、18 件を「読んだ」、7 件を
  「読んでいない」とした。「読んでいない」の 7 件は、どれも記録に読まなかった部分がある（大きな出力のファイルを開かないか
  一部だけを読んだ 3 件、テストだけの差分でテストを外した 1 件、ファイルを読まなかった 3 件）
- #340 のコメントの、担当が同じレベルで回し直した 2 件（#392、#395）は、どちらも最初の周を「読んだ」とする。手作業の grep と
  要らない回し直しが無くなる
- 記録の形が変わると、記録を引けない（`--unlogged` を求める）か、tool の結果を読めずに「読んでいない」とする。どちらも
  黙って通さない
- 指摘のある周は確かめない。指摘を出した後に残りを読まなかった周は見分けない
- 0 件の記録を確かめた後は、返答の読み方の `NOTE:` を出さない（確かめていない `--unlogged` の記録にだけ出す）

### 確認

- `crates/claude-hooks/tests/script_record_local_review.rs`: 読んだ周は記録する（テストと lock の行は求めない）、大きな出力の
  ファイルを開かない周は記録せず `NEXT:` を出す、テストだけの差分はテストの行を求める、前の周の記録とほかのスキルの記録を
  数えない、記録を引けなければ `--unlogged` を求める、読んでいない周は `--unlogged` でも通さない、直した後は前の周から
  変わった行を求める、同じ head の周を合わせて数える
- `crates/claude-hooks/src/rules/count_review_rounds.rs` の `the_line_names_the_session_that_ran_the_round`
