# ADR-0103: 0 件のローカルレビューの記録は、その周の /code-review の記録に PR の差分が入っているときだけ付ける

## 背景

`record-local-review.sh` は、その head で /code-review を呼んだことを count-review-rounds の行で確かめる（#281）が、
呼んだ周が差分を読んだかは確かめない。/code-review の 0 件の返答（low は `(none)`）は、読んだ上での 0 件か、何も読まずに
返した未実施かを、返答からは見分けられない。

- 2026-11-19、low が読まずに `(none)` を返した周が 5 回あった（#340 の本文。テストだけ、文書だけ、大きな差分の周）
- 2026-11-20、low の返答が `(none)` だけの周が少なくとも 6 回あり、扱いが人ごとに分かれた。親は transcript を手で grep して
  確かめ（3 回）、担当 2 人は同じレベルでもう 1 周回し、担当 1 人は transcript で確かめた（#340 の 2026-11-20 のコメント）

/code-review は、Skill の呼び出しごとにサブエージェントを起動し、その記録を
`<設定の場所>/projects/<プロジェクト>/<セッション>/subagents/agent-<id>.jsonl` に、隣の `agent-<id>.forked-skill.json`
（`skillName` が `code-review`、`effort` がレベル）とともに置く。担当（サブエージェント）が回した周も、同じセッションの
`subagents/` に置かれる（2026-11-20 のセッションの `.meta.json` の `spawnDepth` が 2 の記録）。記録の最初の行は
`` Review target: `<対象> <焦点>` `` で始まる依頼文で、tool の結果（`git diff` の出力、Read の本文）は `type` が `user` の行の
`tool_result` に入る。大きな出力はファイルに置かれ、tool の結果は先頭の約 2KB と置き場のパスだけになる。この形は
Claude Code の公開の仕様ではない。

## 決定の要因

- 誤って「読んだ」と判定する（未実施を通す）より、誤って「読んでいない」と判定する（回し直しになる）方がよい
- ただし、読んだ周を常に「読んでいない」とするなら入れる意味が無い。実物の記録で両方の場合を確かめる
- 記録の 1 件ごとに手で grep する作業と、要らない回し直しの両方を無くす

## 検討した案

- 案 A: /git-merge の「終わり」の項に「修正がテスト、`tests/` の下、文書だけのときは medium」と足す（#340 の候補 1）。
  文の規則で、読まれない経路が残る。low が大きな出力のファイルを開かない周（補足の a037d03）は、テストや文書と関わらない
- 案 B: `review-level.sh` が、前の周の HEAD からの差分のうち low の範囲に残る行数で `LEVEL` を決める（#340 の候補 2）。
  回す前のレベルは決まるが、回した周が読んだかは確かめない
- 案 C: `record-local-review.sh` が 0 件の記録のときに「読んだファイル」を引数で受けて差分と照らす（#340 の候補 3）。
  読んだファイルは自己申告のままで、返答と同じく確かめられない
- 案 D（採用）: `record-local-review.sh` が、その周の /code-review の記録の tool の結果に、差分の追加行が入っているかを確かめる

案 D の中で比べた基準（2026-11-20 に、/code-review の記録 97 件で測った。測り方は補足）:

- D1: PR の差分（base...head）の追加行の全部を、1 件の記録に求める。直した後の周は直した差分を焦点に読むので、焦点の周が
  外れる。D4 で「読んだ」とした 0 件の周 18 件のうち 10 件は、追加行の 0〜86% しか入らない（どれも焦点の差分は読んでいた）
- D2: 割合のしきい値（例えば 80%）。ファイルを 1 つ読まなかった周が 93%、96% になり（補足の a016e8f、a02a67d）、しきい値は
  読まなかったファイルを通す
- D3: ファイルごとに 1 行でも入っていれば読んだとする。テストだけの差分で、10 行のうち 2 行だけが入った周（#336 の
  abe31f1。low がテストを外した）を通す
- D4（採用）: 前の周の head から変わった追加行の全部を、その head の周の記録を合わせたものに求める

記録の引き方で比べた案:

- 時刻だけで引く（試作。どのセッションかを問わず、周の行の 90 秒以内に始まった記録）: 別のセッションで同じ頃に回した周を
  分けられず、すべてのセッションの記録を読む
- 記録する側の `CLAUDE_CODE_SESSION_ID` のセッションを探す: 回したセッションと記録するセッションが違う（/clear の後、
  引き継いだ後）と引けない
- 行のセッションの、その head の最初の行より後に始まったすべての記録（実装の最初の版）: 同じセッションで後に回した別の PR の
  周を数え（/delegate の担当は親のセッションを共有する）、`NEXT:` の対象にもした（このブランチの 1 周目のレビューの指摘）
- 行のセッションの、周の行の 60 秒以内に始まったすべての記録（実装の 2 番目の版）: 同じセッションで同じ頃に回した別の
  worktree の周を分けられない（このブランチの 2 周目のレビューの指摘）
- 依頼文の対象が行の worktree と字面で同じ記録だけを取る（実装の 3 番目の版）: 行の worktree は引数の最初の絶対パスの
  ディレクトリか cwd で、対象を書かない、PR の番号を渡した、worktree の下を渡した周の読んだ記録を除く（3 周目のレビューの指摘）
- 依頼文の `Review target:` の後をすべて語に切る（実装の 6 番目の版）: 続く手順の文と焦点の文に出る在るディレクトリ（`/tmp`、
  「searched / failed」の `/`）を対象と読む。2026-11-20 の記録に、周の行に worktree を書いて当てると、97 件のすべてを「記録が
  無い」とした。対象の根を引けないときに対象が行の worktree の下にあるかで比べる版も、`/` で 3 件を除いた。次の版の、
  1 行目だけを読む形は、count-review-rounds が引数の全体から行の worktree を取るので、次の行に書いた別の worktree の周を
  数えた（6 周目のレビューの指摘）
- 依頼文の対象を最初の語で取る（実装の 5 番目の版まで）: 空白を含む worktree のパスと和文が続いたパス（`/repo/wtの差分`）で、
  行の worktree と違うディレクトリになり、読んだ周を除く（5 周目のレビューの指摘）
- 依頼文の対象が行の worktree の下でも上でもない絶対パスの記録を除く（実装の 4 番目の版）: 本体の下の
  `.claude/worktrees/<名前>`（Claude Code の isolation の worktree）の周を本体の周と数える（4 周目のレビューの指摘）
- count-review-rounds の行に回したセッションの ID と worktree を書き、そのセッションの、周の行の 60 秒以内に始まった記録のうち、
  依頼文の対象が絶対パスで、その git の worktree の根（`--show-toplevel`）が行の worktree の根と違うものを除いて取る（採用）: hook は Skill の呼び出しの入力の
  `session_id` と、数えるブランチの worktree（引数の最初の絶対パスのディレクトリか cwd）を持っている。2026-11-20 に、記録
  199 件の始まりが周の行の 1 秒以内だった

tool の結果と求める行の比べ方で比べた案:

- 記録の本文をつないだ 1 つの文字列に、求める行が部分文字列として入っているか（実装の最初の版から PR #400 の Copilot の
  レビューまで）: 長い行の一部や、行をまたぐ文字列でも一致する（Copilot の指摘）
- 行の全体で、diff の `+` と Read の行番号と `path:12:` だけを除いて比べる（その指摘への修正の最初の形）: 2026-11-20 の記録 97 件の
  うち 9 件の読んだ周を「読んでいない」とした。grep -n に 1 つのファイルを渡した出力（`10:+  本文`）が、位置と diff の印の
  両方を持つため
- 行の全体で、位置の接頭辞を除いた形と、それからさらに diff の印を除いた形でも比べる（その次の形）: 97 件の判定は部分文字列の
  版と同じだったが、規則に無い形（git grep の tree の名前の `origin/pr:path:2:`、列の番号、combined diff の `++`、`12: +`）で
  読んだ周を「読んでいない」とした（10 周目のレビューの指摘）
- 行の終わりと合うか（採用）: 接頭辞を問わず、長い行の途中の一部を除く。97 件の判定は部分文字列の版と同じだった
- tool の結果をファイルごと、行ごとに取り出して完全に一致させる: 結果の形（diff、Read、grep、sed）ごとに、どのファイルの
  行かを読む規則が要り、形が変わると読んだ周を「読んでいない」とする

前の周から変わった行の決め方で比べた案:

- `git diff <前の head> <head>` の追加行と PR の追加行の重なり（実装の最初の版）: rebase の後は base の変更を含み、PR が
  足した行と字面が同じ base の行（`}`、`use std::path::Path;` など）だけを求めて、PR の変更を読まない周を通す（1 周目の
  レビューの指摘。テストの `after_a_rebase_lines_the_base_also_added_do_not_stand_for_the_pr`）
- 前の周の PR の差分（PR の base との分かれ目から前の head まで）に無い PR の追加行（採用）。base を引けないときの祖先の
  扱いは、base を merge した head も base の変更を含むので、merge の無い head に限る（2 周目のレビューの指摘。テストの
  `after_merging_the_base_lines_the_base_added_do_not_stand_for_the_pr`）

## 決定と理由

案 D と基準 D4 にする。

- **行**: count-review-rounds は、周の行に回したセッションの ID と worktree（引数の最初の絶対パスのディレクトリか cwd）を足す
  （`<HEAD> <UNIX 秒> <セッション> <worktree>`。worktree は空白を含みうるので行の残り）。前の版の行（2 つの欄）も読む
- **記録を探す**: 0 件の記録のとき、その head の行のセッションの `subagents/` から、`.forked-skill.json` の `skillName` が
  `code-review` で、その head の周の行の 60 秒以内に始まった記録を取る。依頼文の対象（`Review target:` の後の
  /code-review の引数の全体（`` ` `` で始まり、行の終わりの backtick まで。複数の行でもよい。終わりが無ければ 1 行目だけ）を count-review-rounds が引数を切るのと同じ字で切った語のうち、行の worktree と同じく最初の、在るディレクトリの絶対パス）の
  git の worktree の根が行の worktree の根と違えば、別の worktree の周として除く（対象のディレクトリが無い周（対象を書かない、
  PR の番号を渡した、消えた worktree を渡した）と、対象が git の worktree の中に無い周（焦点の文の `/`）は除かない）（設定の場所は
  `CLAUDE_CONFIG_DIR`、無ければ `~/.claude`）。前の周の記録、差分を書いた担当などほかのサブエージェントの記録、同じ
  セッションで回した別の worktree の周の記録は、この周に読んだことを示さないので数えない
- **前の周を引けないとき**: 起動したディレクトリのブランチのファイルに前の周が無い（別の checkout から記録する、ブランチの
  名前を変えた、detached HEAD）なら、PR の差分の全部を求める。読んでいなければ、欠けたファイルを焦点にした周と合わせて数える
- **求める行**: PR の差分（`gh pr diff`）の追加行のうち、前の周の head（起動したディレクトリのブランチのファイルの行で、この head の
  最初の行の前にある別の head。ほかのブランチのファイルの同じ head の行からは決めない）から変わった行。前の周の PR の差分（PR の base の SHA（`baseRefOid`）との分かれ目から前の head まで）に無い行で、
  base を引けなければ、前の head が祖先で、その間に merge が無いときだけ `git diff <前の head> <head>` の追加行と重なる行。
  前の周が無い、変わった行が無い（rebase だけ、消すだけの修正）、base を引けず rebase か base の merge をした head なら、PR の
  差分の追加行の全部。lock のファイル
  （`*.lock`、`*-lock.json`、`*-lock.yaml`）は外す。テストのファイル（/code-review が low で外すと書く `test/`、`spec/`、
  `__tests__/`、`*_test.*`、`*.test.*`、`fixtures/`、`testdata/` に、`tests/`、`test_*`、`*_spec.*`、`*.spec.*` を足したもの。
  大文字と小文字を区別しない）は、
  ほかのファイルの行があれば外す。行は前後の空白を除き、先頭の 200 文字で比べる（Read は 2000 文字を超える行を切る）。
  英数字が 3 字に満たない行（`}`、`Ok(())`）は、ほとんどの tool の結果に入り読んだことを示さないので比べない
- **判定**: その head の周の記録の tool の結果を合わせて行に分け、求める行が全部、どれかの行の終わりと合えば（行の終わりの
  空白を除き、求める行がその行の末尾にあれば）記録する。接頭辞（diff の印、Read の行番号、grep の位置など）は結果の形ごとに
  違うので問わない。先頭の 200 文字で切った求める行は、続きがあるので行の終わりを問わない。1 行でも欠ければ記録せず、
  欠けたファイルと行の数を出し、レベルを 1 段上げて（low は medium、medium と high は high）欠けたファイルを焦点にした
  /code-review を `NEXT:` で示す。焦点の周はそのファイルだけを読むので、前の周と合わせて数える
- **引けないとき**: 行にセッションが無い、記録が無い（別の機械で回した、記録が消えた）、PR の差分を取れない、比べる追加行が
  無い、欠けがあるが xhigh か max の周を含む（子のエージェントに読ませ、子の記録は `.forked-skill.json` を持たないので
  数えない）ときは、`--unlogged <理由>` を求め、理由を記録のコメントに残して付ける（行の無い head の `--unlogged` と同じ
  考え方）。xhigh と max の周を含まずに読んでいないと分かった周（レベルの読めない記録を含む）は、`--unlogged` を付けても付けない
- **変えないもの**: 指摘が 1 件以上の記録と、行の無い head の `--unlogged` の記録は、今までどおり付ける。指摘のある周は、
  指摘が読んだことを示す

テストの形を /code-review が外すと書く形に絞るのは、名前に test を含むだけの本体（`latest.rs`）を外すと、本体を読まない周を
通すため。low が `':!*test*'` のように広く外して本体を読まなかったなら、「読んでいない」として回し直す（決定の要因の向き）。
実装の最初の版は、パスに `test` か `fixture` を含むものを広く外していた（low が外したテストの行を欠けと数えないため）が、
1 周目のレビューが本体を外す反例を挙げた。2026-11-20 の記録 97 件の判定は、この修正を含む 1 周目の修正の前と後で同じだった（補足）。テストだけの差分
では、テストを読まない周を「読んでいない」とする（#340 の本文の #336 の例）。

### 帰結

- 行の終わりと合うかで比べるので、求める行で終わる別の長い行（`// y = x > 0` に対する `x > 0`）でも読んだとみなす。どの
  ファイルの行かも見ないので、同じ行が PR の 2 つのファイルに足されていると、片方のファイルを読んだ周がもう片方も読んだと
  みなされる（どちらも、結果の形ごとに接頭辞とファイルを読む規則が要り、形が変わると読んだ周を「読んでいない」とする）

- 依頼文から引数を読み戻すので、引数の中の行の終わりに backtick がある（焦点の文の終わりの `` `名前` ``）と、引数を短く読み、
  その後に書いた worktree を対象と読まない（同じ頃の別の worktree の周と見分けない側に倒れる）
- `NEXT:` の対象は、worktree の中の依頼文の対象のディレクトリ、無ければ周の行の worktree、それも無ければ起動したディレクトリ
- 対象に絶対パスを書かない周（対象を書かない、PR の番号を渡した）は、同じセッションで 60 秒以内に回した別の worktree の周と
  見分けない。その周の記録も、PR の差分の追加行が全部入っているときだけ数える。/git-merge と /gh-pr-review の回し方は
  `review-level.sh` の `WORKTREE`（絶対パス）を渡すので、普段の周は見分ける

- 2026-11-20 に実物の記録で確かめた結果（補足）では、返答が `(none)` の low の周 25 件のうち、18 件を「読んだ」、7 件を
  「読んでいない」とした。「読んでいない」の 7 件は、どれも記録に読まなかった部分がある（大きな出力のファイルを開かないか
  一部だけを読んだ 3 件、テストだけの差分でテストを外した 1 件、ファイルを読まなかった 3 件）
- #340 のコメントの、担当が同じレベルで回し直した 2 件（#392、#395）は、どちらも最初の周を「読んだ」とする。手作業の grep と
  要らない回し直しが無くなる
- 記録の形が変わると、記録を引けない（`--unlogged` を求める）か、tool の結果を読めずに「読んでいない」とする。どちらも
  黙って通さない
- 指摘のある周は確かめない。指摘を出した後に残りを読まなかった周は見分けない
- 0 件の記録を確かめた後は、返答の読み方の `NOTE:` を出さない（確かめていない `--unlogged` の記録にだけ出す）

### 確認

- `crates/claude-hooks/tests/script_record_local_review.rs`: 読んだ周は記録する（テストと lock の行は求めない）、大きな出力の
  ファイルを開かない周は記録せず `NEXT:` を出す、テストだけの差分はテストの行を求める、前の周の記録とほかのスキルの記録を
  数えない、記録を引けなければ `--unlogged` を求める、読んでいない周は `--unlogged` でも通さない、直した後は前の周から
  変わった行を求める、rebase の後は base が足した行を PR の変更と数えない、同じ head の周を合わせて数える、xhigh と max の
  周は `--unlogged` を求める、レベルの読めない周は確かめる、別の worktree の同じ頃の周を数えない、対象に worktree を書かない
  周は行の worktree の周と数える、本体の下に置いた worktree の周は本体の周と数えない、UTF-8 でないバイトを含む記録も読む、
  壊れた時刻の行で溢れない
- 同じファイルの単体テスト: テストのファイルの形、英数字が 3 字に満たない行を比べないこと、引用したパスを戻すこと、
  依頼文の対象の切り方
- 結合テストの `the_previous_round_is_taken_from_the_branch_of_the_clone`、`a_required_line_must_end_a_line_of_a_tool_result`、
  `a_required_line_may_follow_any_prefix_of_a_tool_result_line`
