# ADR-0098: 担当の報告に外したもの、後回しにしたものの欄を置き、hook で確かめる

## 背景

2026-11-19 に xlc のセッションで、測られないまま残った前提、外したまま戻していない核種、検査から外した 555 ファイル、
open の issue 200 件が同じ日に見つかった。ユーザーは、親が方針を先へ進むのに都合のよい側に解釈していたとし、個々の誤読を
直すのでなく、都合のよい解釈が起きない進め方に変えることを求めた。除外のたびにユーザーの判断を求める形にはせず、既定は
外さずに原因を直すこととした。issue はブランチを 1 つのトピックに保つ仕組みで、放置してよい意図は無いとした
（ユーザー 2026-11-19 の発言の要約。/btw での発言を親が依頼に要約したもの）。

担当の報告（/delegate の references/working.md の手順 9）は、「親が先に読む要点」から「続きの作業」までの節を持つが、
検査や対象から外したもの、skip、条件を狭めて通したもの、測らずに置いた値は、「決めたことと根拠」「確かめていないこと」
「対応しなかった指摘」に散って書かれるか、書かれない。親は要点と確認の結果を先に読むので、外して通した対処は、成功の報告の
中に埋もれる。外さずに直す規則の文は既にグローバルの CLAUDE.md の「テスト」の項にあり、それでも外して通す対処が残った。

xlc の 2026-11-19 の会話の記録（`~/.claude/projects/-home-tagawa-github-xlc/` の、その日に更新された jsonl 47 本）では、
担当の報告は SendMessage（`to: "main"`。マージの許可を求める報告）と SubagentHandback で親に届く。その 2 つのツールの
呼び出し 141 件のうち、行頭の `## 親が先に読む要点` を持つものは 12 件（2 件は `## 親が先に読む要点（管理のセッション
向けの要約）`、1 件はこの節を最後に置いた報告）で、どれも担当の報告だった。ほかの 129 件はこの見出しを持たない（行の途中に
この語を含む親の指示が 2 件）。

## 検討した案

欄の置き方:

- 案 A: 報告に「外したもの、後回しにしたもの」の欄を足し、「親が先に読む要点」の直後に置く。無ければ「なし」と書く
- 案 B: 既存の「確かめていないこと」と「対応しなかった指摘」に書かせる文を足す。散った置き場は変わらず、親が先に読む位置に
  来ない。文を足す形は背景のとおり効かなかった
- 案 C: 外すたびにユーザーの判断を求める。ユーザーが退けた（判断を増やす形にはしない）

確かめ方:

- 案 1: PreToolUse の hook（claude-hooks）で、SendMessage と SubagentHandback の `message` に行頭の `## 親が先に読む要点`
  があれば、次の `##` の見出しが `## 外したもの、後回しにしたもの` で、その中身が空でないことを確かめる。報告の形の有無は
  文字列だけで決まる（ADR-0061 の依頼の欄と同じ）
- 案 2: 親が報告を受けたときに読んで確かめる（requesting.md の文だけ）。親が要点だけを読んで進んだのが今回の件で、案 B と
  同じく文に頼る
- 案 3: 報告の全部の節を確かめる。途中で止まった報告や、調べるだけの依頼で節を替えた報告（`## 調べて分かったこと`。
  2026-11-19 の記録に 1 件）を止め、誤検知が出る。今回の件に要るのは新しい欄だけ

対象の決め方:

- 行頭の `## 親が先に読む要点`（後ろに括弧の限定が続いてもよい）を、コードブロック（```` ``` ````）の外に持つ呼び出し
  だけを見る。報告の書式の最初の見出しで、行の途中でこの語に触れる親の指示と、報告をコードブロックに入れて引用する文を
  見ない

## 決定と理由

採用: 案 A と案 1。

- 報告の書式（references/working.md の手順 9）の「親が先に読む要点」の直後に `## 外したもの、後回しにしたもの` を置く。
  中身は、検査や対象から外したもの、skip、条件を狭めて通したもの、issue にして残したレビューの指摘、測らずに置いた値や組。
  無ければ「なし」
- 頼む側（references/requesting.md の「報告を受けたら」）は、この欄を確認の結果より先に読み、外して通した対処は差し戻す
- 担当の「作業中の規則」に、計算や検査が通らないときは原因を調べて直し、直せなければ止めて親に知らせる項を置く（対象、検査、
  条件を外して通さない。外すかの判断をユーザーに回さない）
- claude-hooks の delegate-report-fields が、SendMessage と SubagentHandback の `message` を案 1 のとおり確かめ、欄が無いか、
  位置が違うか、中身が空なら、修正方法を添えて止める。エスケープは無い（欄を足す以外に直す方法が無い。ADR-0061 と同じ）。
  claude-setup の PreToolUse の matcher に SendMessage と SubagentHandback を足す

親が先に読む位置に置くのは、外して通した対処が成功の報告に埋もれたのが背景の件だから。欄を必須にして「なし」を書かせるのは、
欄が無いことと、外したものが無いことを区別するため。中身（外したものを全部書いたか）は文字列から決まらないので判定しない。

### 帰結

- hook は、中身の正しさでなく、欄があることだけを保証する。外したことを書かない報告は、親の読みとレビューで拾う
- 誤検知が出うるのは、報告の形をコードブロックの外に引用したメッセージと、報告の書式を真似た別の用途のメッセージだけで、
  修正方法（欄を足すか、引用をコードブロックに入れる）は拒否の文言に示す
- PreToolUse の hook が SubagentHandback の呼び出しで走るかは、この ADR の時点で確かめていない（手元の `claude -p` の
  試しでは、前景のサブエージェントが SubagentHandback を使わずに終わり、決められなかった）。走らなければ、SendMessage で
  送るマージの許可の報告だけが確かめられる。マージの後の rebuild で、担当の報告が止まるかを親が確かめる

### 確認

- `crates/claude-hooks/src/rules/delegate_report_fields.rs` のテスト（欄の有無、位置、空の中身、コードブロックの中の見出し、
  対象外のツールとメッセージ）
- `crates/claude-setup/tests/settings.rs`（matcher）
- 2026-11-19 の xlc の記録から取り出した 141 件の呼び出しを `claude-hooks pre-tool-use` に流した結果（PR の本文）
