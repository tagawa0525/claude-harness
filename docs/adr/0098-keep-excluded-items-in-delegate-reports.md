# ADR-0098: 担当の報告に外したもの、後回しにしたものの欄を置き、hook で確かめる

## 背景

2026-11-19 に xlc のセッションで、測られないまま残った前提、外したまま戻していない核種、検査から外した 555 ファイル、
open の issue 200 件が同じ日に見つかった。ユーザーは、親が方針を先へ進むのに都合のよい側に解釈していたとし、個々の誤読を
直すのでなく、都合のよい解釈が起きない進め方に変えることを求めた。除外のたびにユーザーの判断を求める形にはせず、既定は
外さずに原因を直すこととした。issue はブランチを 1 つのトピックに保つ仕組みで、放置してよい意図は無いとした
（ユーザー 2026-11-19 の発言の要約。/btw での発言を親が依頼に要約したもの）。

担当の報告（/delegate の references/working.md の手順 9）は、「親が先に読む要点」から「続きの作業」までの節を持つが、
検査や対象から外したもの、skip、条件を狭めて通したもの、測らずに置いた値は、「決めたことと根拠」「確かめていないこと」
「対応しなかった指摘」に散って書かれるか、書かれない。親は要点と確認の結果を先に読むので、外して通した対処は、成功の報告の
中に埋もれる。外さずに直す規則の文は既にグローバルの CLAUDE.md の「テスト」の項にあり、それでも外して通す対処が残った。

xlc の 2026-11-19 の会話の記録（`~/.claude/projects/-home-tagawa-github-xlc/` の、その日に更新された jsonl 47 本）では、
担当の報告は SendMessage（`to: "main"`。マージの許可を求める報告）と SubagentHandback で親に届く。その 2 つのツールの
呼び出し 141 件のうち、行頭の `## 親が先に読む要点` を持つものは 12 件（2 件は `## 親が先に読む要点（管理のセッション
向けの要約）`、1 件はこの節を最後に置いた報告）で、どれも担当の報告だった。ほかの 129 件はこの見出しを持たない（行の途中に
この語を含む親の指示が 2 件）。

## 検討した案

欄の置き方:

- 案 A: 報告に「外したもの、後回しにしたもの」の欄を足し、「親が先に読む要点」の直後に置く。無ければ「なし」と書く
- 案 B: 既存の「確かめていないこと」と「対応しなかった指摘」に書かせる文を足す。散った置き場は変わらず、親が先に読む位置に
  来ない。文を足す形は背景のとおり効かなかった
- 案 C: 外すたびにユーザーの判断を求める。ユーザーが退けた（判断を増やす形にはしない）

確かめ方:

- 案 1: PreToolUse の hook（claude-hooks）で、SendMessage と SubagentHandback の `message` に行頭の `## 親が先に読む要点`
  があれば、次の `##` の見出しが `## 外したもの、後回しにしたもの` で、その中身が空でないことを確かめる。報告の形の有無は
  文字列だけで決まる（ADR-0061 の依頼の欄と同じ）
- 案 2: 親が報告を受けたときに読んで確かめる（requesting.md の文だけ）。親が要点だけを読んで進んだのが今回の件で、案 B と
  同じく文に頼る
- 案 3: 報告の全部の節を確かめる。途中で止まった報告や、調べるだけの依頼で節を替えた報告（`## 調べて分かったこと`。
  2026-11-19 の記録に 1 件）を止め、誤検知が出る。今回の件に要るのは新しい欄だけ

対象の決め方:

- 行頭の `## 親が先に読む要点`（後ろに括弧の限定が続いてもよい）を、コードブロック（```` ``` ````）の外に持つ呼び出し
  だけを見る。報告の書式の最初の見出しで、行の途中でこの語に触れる親の指示と、報告をコードブロックに入れて引用する文を
  見ない

## 決定と理由

採用: 案 A と案 1。

- 報告の書式（references/working.md の手順 9）の「親が先に読む要点」の直後に `## 外したもの、後回しにしたもの` を置く。
  中身は、検査や対象から外したもの、skip、条件を狭めて通したもの、issue にして残したレビューの指摘、測らずに置いた値や組と
  仮定。無ければ「なし」。仮定は「確かめていないこと」の節から、この欄に移す（置き場を 1 つにする）
- 頼む側（references/requesting.md の「報告を受けたら」）は、この欄を確認の結果より先に読む。外して通した対処（通らなかった
  ものを通すために、原因を直さずに外すか狭めたもの、skip、tolerance の緩和、期待値の曖昧化。TDD の RED の skip は別）と、
  同じトピックの直し残しを issue にしたものは差し戻す。通らなかったものを通すためでなく、理由があって範囲から外したものと、
  別のトピックと振り分けて issue にした指摘は受け入れてよい。どちらか分からなければ、通らなかったものがあったかを担当に
  尋ねて決める。測らずに置いた値や組と仮定は受け入れず、親が確かめられるなら確かめ、確かめられなければ担当に測る指示で
  差し戻す。担当にも親にも確かめられない事実は、マージの許可を送らずにユーザーに確かめる（自分も担当なら、止めて自分の
  親に知らせる）。受け入れたものは、担当にマージの許可を送る前のユーザーへの報告（自分も担当でユーザーに報告できない
  ときは、自分の報告のこの欄）に、何を、なぜ外したかと戻す条件を必ず書く
- 担当の「作業中の規則」に、計算や検査が通らないときは原因を調べて直し、直せなければ止めて親に知らせる項を置く（対象、検査、
  条件を外して通さない。外すかの判断をユーザーに回さない）
- claude-hooks の delegate-report-fields が、SendMessage と SubagentHandback の `message` を案 1 のとおり確かめ、欄が無いか、
  位置が違うか、中身が空なら、修正方法を添えて止める。エスケープは無い（欄を足す以外に直す方法が無い。ADR-0061 と同じ）。
  claude-setup の PreToolUse の matcher に SendMessage と SubagentHandback を足す

親が先に読む位置に置くのは、外して通した対処が成功の報告に埋もれたのが背景の件だから。欄を必須にして「なし」を書かせるのは、
欄が無いことと、外したものが無いことを区別するため。中身（外したものを全部書いたか）は文字列から決まらないので判定しない。

### 帰結

- hook は、中身の正しさでなく、欄があることだけを保証する。外したことを書かない報告は、親の読みとレビューで拾う
- 入れ子の担当（自分も担当である親）が受け入れた除外は、自分の報告の欄で上に渡るので、ユーザーに届くのが、その担当の
  頼んだ担当のマージの後になることがある
- 親が受け入れた除外は、親からユーザーへの報告で見える。この報告は自由な文で、機械は確かめない。受け入れるかの判断は親に
  残るが、受け入れたものが 1 つずつユーザーに届くので、ユーザーが戻すよう言える
- 誤検知が出うるのは、報告の形をコードブロックの外に引用したメッセージと、報告の書式を真似た別の用途のメッセージだけで、
  修正方法（欄を足すか、引用をコードブロックに入れる）は拒否の文言に示す
- PreToolUse の hook が SubagentHandback の呼び出しで走るかは、この ADR の時点で確かめていない（手元の `claude -p` の
  試しでは、前景のサブエージェントが SubagentHandback を使わずに終わり、決められなかった）。走らなければ、SendMessage で
  送るマージの許可の報告だけが確かめられる。マージの後の rebuild で、担当の報告が止まるかを親が確かめる

### 確認

- `crates/claude-hooks/src/rules/delegate_report_fields.rs` のテスト 22 件（欄の有無、位置、空の中身、括弧の限定と入れ子、
  ATX の見出しの形と字下げ、` と ~ のフェンス、行頭のコードスパン、閉じないフェンス、拒否の文に ADR の番号が無いこと）と、
  `rules::tests::report_tools_run_only_the_delegate_report_check`、`crates/claude-setup/tests/settings.rs`（matcher）が通る
- 2026-11-19 の xlc の記録から取り出した 141 件の呼び出しを、このブランチでビルドした `claude-hooks pre-tool-use` に
  流すと、`## 親が先に読む要点` を持つ 12 件だけが止まり、ほかの 129 件は止まらない。12 件の要点の節の直後に
  `## 外したもの、後回しにしたもの` と「なし」を足すと、12 件とも通る

## 変更

- 2026-11-19: 頼む側が受け入れた除外の扱い。前は「頼む側（references/requesting.md の「報告を受けたら」）は、この欄を確認の
  結果より先に読み、外して通した対処は差し戻す」。決めた同じ日に、親のセッション（xlc と claude-harness）が、比べる条件を
  そろえるための除外のような、理由があって範囲から外したものを受け入れていて、
  例外を認めないと読める文と行動が食い違った。担当の「作業中の規則」（通らないときに、外して通さない）は変えない。差し戻すのは
  通らなかったものを通すために外した対処で、受け入れてよいのは、それに当たらない、理由のある範囲の除外。下の初めの 3 つの
  案をユーザーに示し、3 つ目を採った（ユーザー 2026-11-19）。4 つ目は、その後に比べた
  - 差し戻すのを「原因を直せるのに外したもの」に狭めるだけの案は、文と運用は合うが、受け入れたものがユーザーから見えない
    まま、判断が親に任される（この ADR が止めようとした、都合のよい側の解釈で通す余地）ので採らなかった
  - 文を変えず、除外をすべて差し戻して、受け入れたいものはユーザーに確かめる案は、抜け道は無いが、理由の明らかな除外でも
    往復とユーザーへの確認が増えるので採らなかった
  - 採った案: 親は理由のある範囲の除外を受け入れてよいが、受け入れたものをユーザーへの報告に必ず書く。判断は 1 つ目の案と
    同じく親に残るが、受け入れたものが 1 つずつユーザーに届く点が違う。担当の報告に置いた見える化を、親からユーザーへの
    報告にも置く。報告の文は自由な文で、機械では確かめない。ユーザーへの報告に決まった節を置く形は、指示を増やさない方を
    選び、足さない（ユーザー 2026-11-19 は、どちらでもよいと答えた）。知らせるのは担当にマージの許可を送る前で、返事は
    待たない（マージの後に初めて知らせる形だと、ユーザーが戻すよう言う前に main に入る）
  - 同じ変更で、差し戻すものと受け入れないものの範囲も書いた。差し戻す通し方に tolerance の緩和と期待値の曖昧化を足し、
    TDD の RED の skip を除いた（グローバルの CLAUDE.md の「テスト」の項と同じ範囲）。別のトピックと振り分けて issue にした
    指摘は受け入れてよい側に置いた。測らずに置いた値や組と仮定は、前の文では扱いが無く、受け入れない（親が確かめる、担当に
    測らせる、どちらにも確かめられない事実はユーザーに確かめる）と書いた。確かめられない仮定を「確かめていない仮定」として
    報告に書いて進める形も比べたが、背景の、測られないまま残った前提をまた通すので採らなかった。ユーザーに聞くのは事実で、
    外してよいかの判断ではないので、担当の規則（外してよいかをユーザーに聞く形にしない）とは食い違わない
  - 担当が欄の行ごとに「通すため」か「範囲」かの印を付け、hook がそれを確かめる案は、印を付けるのが担当の自己申告で、
    言い換えれば通るので採らなかった
