# ADR-0108: Stop の hook（claude-hooks stop）で、最後の応答が日本語で書かれていなければ終了コード 2 で応答を続けさせ、日本語で書き直させる

## 背景

ハーネスの静的な設定（`claude-settings.json`）は `"language": "Japanese"` を置き、Claude Code はシステムプロンプトの
Language の節で、ユーザーへの応答を日本語で書くよう指示する。それでも、長い作業の後の最後の報告が英語になる失敗が、
NC リポジトリの 1 つのセッション（`06ef8793`）で 2 回あった。ユーザーは 2 回とも、日本語で応答するよう訂正した（ユーザー
2026-11-27）。記録で確かめると、1 回目（記録の 873 行目）は Bash と Write の長い呼び出しの列の後の報告で、2 回目（5709 行目）は
サブエージェントの英語の報告を受けた後の報告だった。どちらも、本文に日本語の文字が 1 つも無い。

同じ機械の `~/.claude/projects/*/*.jsonl`（サブエージェントの記録を除く）の、`stop_reason` が `end_turn` で本文のある
アシスタントの応答 877 件（2026-11-27 に数えた）のうち、日本語の文字（かな、漢字）が 0 の応答は 22 件で、NC のほかに
lineage-grid と claude-harness のセッションにもあった。

ユーザーは、振り返りの提案のうち、この検査の置き場をハーネス（グローバル）にする案を採った（ユーザー 2026-11-27）。

Stop の hook の入力と出力（Claude Code の hooks の文書の Stop の節。2026-11-27 に https://code.claude.com/docs/en/hooks.md で
読んだ）:

- `last_assistant_message` は最後の応答の本文。`transcript_path` の記録は非同期に書かれ、Stop の時点で最後の応答を
  含むとは限らないので、最後の応答の本文にはこの値を使う、と文書は勧める
- `stop_hook_active` は、Stop の hook が応答を続けさせた後の Stop で `true`。続けさせるのは連続で 8 回までで、ツールを
  呼ぶと数え直す
- 終了コード 2 は応答を続けさせ、標準エラーが続ける理由として Claude に渡る。同じイベントの hook は並べて走る

今の Stop の登録は `claude-hooks stop` の 1 件で、自動メモリを `refs/memory-backup` に退避し、0 と 1 のほかで終えない
（ADR-0076、ADR-0089）。

## 決定の要因

- 誤って止めない。誤って止めると、応答の終わりごとに書き直しの手戻りが出る。コード、パス、識別子、英語の引用の多い日本語の
  応答、本文の短い応答、本文の無い応答は通す
- 英語で書いた報告を、ユーザーが読む前に直させる
- 自動メモリの退避（ADR-0076）を弱めない。退避の失敗は利用者に見える
- `claude-setup` と `claude-hooks` の版がずれたとき（ADR-0089 の帰結）に、応答の終わりごとに止めない
- 依存を足さない

## 検討した案

置き場:

- 案 1: `claude-hooks stop` に足す。退避の後に検査し、登録は今の 1 件のまま変えない
- 案 2: 新しいサブコマンド（`claude-hooks stop-japanese` など）にし、`claude-setup settings --stop` が Stop にもう 1 件
  登録する。退避と並べて走り、終了コードも別になる。前の版の `claude-hooks` は知らないサブコマンドに使い方を出して 2 で
  終えるので、新しい settings.json と前の版のバイナリがそろわない間（Windows で `claude-setup` だけを新しくした、
  home-manager の前の世代に戻した）は、応答の終わりごとに応答を続けさせる
- 案 3: 判定をモデルに任せる prompt hook（`type: "prompt"`）にする。応答ごとに API を呼ぶ時間と費用がかかり、判定が
  揺れる

判定:

- 案 A: 本文から、コードブロック、インラインのコード、引用のブロックを除き、空白と日本語の文字で区切った語のうち
  ASCII の英字だけでできた語（`'` と `-` でつないだものを含む。パス、`snake_case`、`file.ext`、URL のような記号や数字を
  含む語は数えない）を英語の語として数え、かなと漢字の数と比べる。英語の語が 15 以上で、かなと漢字が 20 未満なら英語と見る
- 案 B: かなと漢字の、ASCII の文字に対する割合で見る。日本語の前置きに英語の長い文（引用の印の無いログなど）が続く
  応答を、前置きが 20 字以上でも、英語の長さに比べて短ければ英語と見る
- 案 C: 言語判定の crate（`whatlang` など）を使う。依存が増え、コードと識別子の多い日本語の応答で外れうる

続けさせた後:

- 案 ア: `stop_hook_active` が `true` なら検査しない（書き直しても英語のままなら、そのまま止める）
- 案 イ: 毎回検査し、Claude Code の 8 回の上限に任せる

## 決定と理由

採用: 案 1、案 A、案 ア。

- 置き場: `claude-hooks stop` が、退避を済ませてから `last_assistant_message` を検査する。英語と見たら、1 行目に
  `claude-hooks stop: 最後の応答が日本語で書かれていません` で始まる理由と、日本語で書き直す修正方法を出して 2 で終える。
  同じ回に退避も失敗していれば、退避の失敗の行も続けて出す（2 では標準エラーが Claude に渡り、利用者の通知には出ないが、
  書き直した応答の Stop で退避をやり直し、失敗すれば 1 で通知に出る）。登録と timeout は変えない
- 止めない場合: hook の JSON が読めない、`last_assistant_message` が無いか文字列でない、本文が短い（英語の語が 15 未満）、
  `stop_hook_active` が `true`
- 判定: 案 A。数え方の規則（除くもの、語の形、閾値）は `crates/claude-hooks/src/response_language.rs` に置き、
  Markdown のブロックは、ほかの crate（design-records、fix-markdown-lint、ja-terms）と同じ pulldown-cmark で読む
  （claude-hooks は design-records を通して既に pulldown-cmark に依存している）

理由:

- 案 1: 登録が変わらないので、`claude-setup` と `claude-hooks` の版がずれても、前の版のバイナリは今までどおり退避だけを
  行い、新しいバイナリは前の settings.json のまま検査する。案 2 は、版のずれの間に、応答の終わりごとに使い方の文で応答を
  続けさせる（8 回まで）。これは誤って止めることそのもので、判断の軸に反する。案 1 の費用は、退避のロックの待ち（最大 30 秒）
  の間は検査も待つことと、退避の失敗と英語が同じ回に重なると、退避の失敗が通知でなく Claude に渡ることで、どちらも次の
  Stop で解ける。案 3 は、応答ごとの API の時間と費用に見合わない（案 A で記録の英語の応答を分けられた。下の理由）
- 案 A: 記録の 877 件で、英語と見たのは 12 件で、どれも日本語の文字が 0 の英語の応答だった。日本語の文字が 1 以上の
  応答で、かなと漢字が 60 未満のまま英語の語が 8 以上あるものは無かった（閾値の 15 と 20 から離れている）。案 B は、
  日本語の前置きに引用の印の無い英語が続く応答を、前置きの長さによらず英語の長さで止める（案 A が止めるのは、前置きが
  20 字未満のときだけ）。閾値を 15 語にしたのは、「The checks passed. Waiting for the
  review.」のような 1 文の英語の応答を通すため（短い応答を止めない判断の軸）
- 案 ア: 書き直しても英語のままのときに、続けて止めても直る見込みが小さく、手戻りだけが増える

### 帰結

- 英語の語が 15 未満の英語の応答は通る。記録の 22 件のうち 10 件（待ちの知らせの 1 文など）がこれに当たる
- 日本語の文字が 20 以上ある英語の応答（日本語の長い引用を含むもの）は通る
- 日本語の前置きが 20 字未満で、引用の印もコードブロックも無い英語（ログ、英語のコミットのメッセージ）が続く日本語の
  応答は返る。実装したバイナリを当てた 881 件（下の確認）には無かった。返す理由に、英語のまま残す文（求められた英語の
  本文、ログ、英語の引用）を訳さず、コードブロックか `>` で始まる引用のブロック（どちらも数えない）に入れ、日本語の説明を
  添える修正方法を書くので、書き直しは 1 回で済む（ローカルレビューの指摘で足した）
- ユーザーかスキルが英語の本文（英語のメール、PR の本文、翻訳）を求めた応答も、本文が英語なら返る。修正方法は上と同じ
- `stop_hook_active` は、どの Stop の hook が続けさせた後でも `true` になる。ほかの Stop の hook（プラグイン、利用者の
  hook）が応答を続けさせた後の英語の応答は、検査しない。2026-11-27 の時点で、ハーネスの Stop の hook はこの 1 件だけ
- Stop はサブエージェントの終わりには走らない（SubagentStop）ので、サブエージェントの英語の報告は検査しない
- 登録は変えないので、配備（rebuild、Windows は `cargo install`）で `claude-hooks` を入れ直せば効く。`claude-setup` の
  settings を再実行する必要は無い

### 確認

- `claude-hooks` の結合テスト（`tests/stop.rs`）: 英語の応答は 2 で終え、1 行目に理由を出し、退避もする。コード、パス、
  識別子、英語の引用の多い日本語の応答、英語の語が 15 未満の応答、本文の無い入力、読めない JSON、`stop_hook_active` が
  `true` の入力は 0 で終える。退避が失敗した回の英語の応答は 2 で終え、退避の失敗の行も出す
- 数え方の単体テスト（`src/response_language.rs`）: コードブロック、インラインのコード、引用のブロック、パスと識別子を
  数えない
- 実装したバイナリに、手元の記録の最後の応答 881 件（2026-11-27。上の 877 件に、数えた後の同じ日の 4 件が加わったもの）を
  `last_assistant_message` として渡すと、2 で返したのは上と同じ 12 件で、ほかは返さなかった
