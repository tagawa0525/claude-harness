# ADR-0091: 同期で配ったファイルの一覧を ~/.claude に残し、ソースから消えたものだけを次の同期で消す

## 背景

`claude-setup sync`（ADR-0084。Linux の `claude-sync` も呼ぶ）は、ソースに無いファイルを消さず、手で足したものを残す。
このため、リポジトリから消した `remap-commit-refs.sh`（`d792c397`、2026-10-11）が `~/.claude/scripts` に残り続け、
スキルが「古いコピーは使わない」と注記する事態になった（手で消して解消。#24）。

手で足したファイルを残す要求と、リポジトリから消した物を消す要求は両立させる必要がある。どちらも
「ソースに無い」ファイルで、同期の時点のソースと ~/.claude の中身だけでは区別できない。

## 検討した案

- 案 1: 同期のたびに配ったファイルの一覧（manifest）を残し、前の一覧にあって今のソースに無いものだけを消す
- 案 2: skills と scripts を `rsync --delete` 相当で丸ごとソースに合わせ、手で足す置き場を別のディレクトリ
  （例: `~/.claude/local/`）に分ける
- 案 3: 今のまま消さず、利用者が手で消す

### 各案の長所と短所

- 案 1: 長所は、手で足したファイルが一覧に無いので、今の置き場のまま残ること。既存の利用者の移行が要らない。
  短所は、一覧という状態が増え、壊れた一覧を信用すると誤って消しうること（下の安全性で抑える）
- 案 2: 長所は、状態が無く、ソースと同じになること。短所は、すでに skills と scripts に手で足したファイルが、
  切り替えの同期で全部消えること（移行の手当てが要る）。Claude Code が `~/.claude/skills` に置くスキルも消える
- 案 3: 長所は実装が要らないこと。短所は、#24 のとおり古いコピーが使われ続けること

## 決定と理由

採用: 案 1。

- 一覧の置き場と形式: `~/.claude/.claude-sync-manifest`。1 行 1 パスで、`~/.claude` からの相対パス、区切りは OS によらず `/`。
  ソートして書く。隣の一時ファイルに書いて名前を付け替える（既存の `replace_with`）
- 配布物の範囲: `skills/` と `scripts/` の下のファイルと symlink（ディレクトリは載せず、symlink は辿らない）。
  `CLAUDE.md` はソースに常にあるので載せず、`commands/` は利用者が手で直す物を残す規則（ADR-0084）なので載せない。
  外部のスキル（flake の input）は rebuild の activation が配り、`sync` が配った物ではないので載せない（消さない）
- 消す条件: 前の一覧にあって、今回配った物に無いファイルと symlink だけ。消した後、空になった親のディレクトリも
  `skills`、`scripts` の手前まで消す（中身があれば残る）
- 初回（一覧が無い）: 何も消さず、一覧だけを作る。前の版が配った物か手で足した物かを区別できないため
- 一覧は、全部の場所のコピーが成功した後で書く。コピーが失敗して止まれば、前の一覧のままで、次の同期でもう 1 度試す
- パスの安全性: 一覧は書き換えられうるので、行を信用しない。次を満たす行だけを消す。満たさない行は黙って飛ばす
  - 先頭が `skills/` か `scripts/` で、その下に 1 つ以上の要素がある
  - 空、`.`、`..` の要素、絶対パス、`\`、NUL を含まない（`~/.claude` の外と、`settings.json` など別の物に届かない）
  - `~/.claude` から最後の手前までの親が、どれも symlink でない（`~/.claude/skills` が外を指していても、その先を消さない）
  - 最後の要素がディレクトリなら消さない。symlink ならリンクだけを消し、行き先は消さない
- 消せなかったときは、標準エラーに出して同期は続ける（消えない古いコピーより、新しい版の配布を止めない）

「消さない」ことで手で足した物を守っていた方針（ADR-0084）は、一覧に載っていない物だけを守る形に置き換える。

### 帰結

- 同期のたびに、一覧の読み書きが 1 回増える
- 一覧を消すと、次の同期は初回と同じになり、そのとき残っている古いコピーは一覧に載らないまま残る（手で消す）
- 手で足したファイルが、のちにリポジトリに同じパスで入ると、次の同期から一覧に載り、ソースから消えたとき消える
